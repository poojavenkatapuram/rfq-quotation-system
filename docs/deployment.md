# ForgeFlow free-tier deployment guide

This repository includes a Render Blueprint template for a **new, public demo deployment**. No service, database, bucket, migration, or public URL has been created by this change. Do not import the Blueprint or make the service public until the Company A data classification, account ownership, and public-demo approval are settled.

## Recommended ₹0 architecture

- **Frontend:** Render Static Site (free).
- **API:** Render Web Service, `plan: free` (free, single instance).
- **PostgreSQL:** a new Neon Free project. As listed by Neon in October 2026, Free includes 1 GB database storage and 100 compute-hours per project per month. The project scales to zero and has a 6-hour instant-restore window; treat it as a demo database, not a backup strategy. See [Neon's current Free plan announcement](https://neon.com/blog/neon-free-plan-1-gb-per-project).
- **Uploaded files:** a private Cloudflare R2 Standard bucket. Its current free allowance includes 10 GB-month storage, 1 million Class A requests, 10 million Class B requests per month, and free egress. Keep the bucket private and use bucket-scoped server credentials; do not enable public bucket access. See [R2 pricing](https://developers.cloudflare.com/r2/pricing/) and [R2 S3 compatibility](https://developers.cloudflare.com/r2/get-started/s3/).

These usage allowances make the plan $0 while usage remains within every provider's limits. R2 describes a subscription/checkout flow to activate its API; do not continue if the account asks for a paid plan or a payment commitment inconsistent with the ₹0 budget. Configure provider spend alerts/limits where available. Render can suspend free services when included bandwidth or build minutes are exhausted. Its free API sleeps after 15 minutes idle, takes about a minute to wake, has an ephemeral filesystem, and cannot use a persistent disk, shell/SSH, or pre-deploy command. See [Render Free services and restrictions](https://render.com/docs/free) and [pre-deploy command support](https://render.com/docs/deploys#pre-deploy-command).

The API stores new uploaded documents in R2 when `RFQ_DOCUMENT_STORAGE_PROVIDER=r2`. Existing filesystem-backed `storagePath` records remain readable by the local provider; a new hosted deployment should use a fresh database and has no old local upload files to migrate. No Prisma schema change is required: the existing field stores an opaque storage reference. PDF quotations are generated when requested and are not persisted as uploaded files.

If the deployment must carry forward any existing RFQ/quotation records, treat that as a separate approved data migration. Existing `storagePath` values point at local files, and those files are not automatically present in R2. Copy authorized source files into the private bucket and update only the corresponding new-database references under a reviewed migration procedure; do not simply restore a database dump into the free service and assume downloads will work. No existing records or files are copied by this branch.

## Before provisioning

1. Obtain explicit approval to expose a public demo and decide whether synthetic data only will be used. Do not upload real customer RFQs or drawings to a public assignment demo without Company A approval.
2. Create a **new empty** Neon project and a **private Standard** R2 bucket in your own accounts. Choose nearby regions if offered. Do not reuse `rfq_quotation_db`, `forgeflow_synthetic_demo_test`, or any business database.
3. In R2, create credentials limited to object read/write for that bucket. Keep the account ID, bucket name, access key ID, and secret access key private.
4. Confirm Neon and R2 remain at $0 under their free allowances and that account billing settings cannot incur unwanted charges. Stop if a payment method, paid tier, or spend commitment is required.

## Deploy from Render Blueprint

1. Connect the repository and select branch `deployment/free-tier` only after the change set has been reviewed and separately pushed/approved. This guide does not authorize a push.
2. Review `render.yaml` in the Blueprint preview. Confirm the API plan is `free`, no `disk` or `preDeployCommand` appears, and the only resources are a free API and static site. Do not click deploy until public exposure is approved.
3. Supply the API's `DATABASE_URL` from the new Neon project, `CLIENT_URL` after Render assigns the static-site HTTPS origin, and the four `R2_*` values through Render's secret/environment UI. Keep `JWT_SECRET` generated by Render. Never add secrets to Git or `VITE_*` variables.
4. The free API's start command runs `npx prisma migrate deploy && npm start`. Render does not provide a free pre-deploy command; therefore the existing checked-in migrations run as a startup precondition and are rechecked (no-op when current) at each process start. Verify the database target in Render before the first start. This command does not reset, seed, or use `db push`.
5. Set the static site's `VITE_API_BASE_URL` to the API HTTPS origin followed by `/api`. Set API `CLIENT_URL` to the static site's exact HTTPS origin (origin only). This preserves exact-origin CORS.
6. Confirm `/api/health` and `/api/health/database` return success. Provision the first Admin using the documented protected bootstrap procedure against this new database; do not use existing local credentials or seed real customer data. Provision role-specific demo users using the Admin UI.
7. Use only explicitly synthetic files. Verify upload, download authorization, and object persistence after an API restart/redeploy. Verify inaccessible roles receive authorization failures.

## AI inference under a ₹0 budget

The application supports Ollama-compatible HTTPS endpoints through the backend-only `OLLAMA_RFQ_BASE_URL` and `OLLAMA_API_KEY` settings. The checked-in Blueprint keeps `LOCAL_AI_ENABLED=false`; this is explicit because enabling remote inference sends extracted RFQ text to a third party. Do not send Company A document content without written data-processing approval.

Ollama's pricing page currently advertises a $0 Free tier with starter usage credits and access to starter models. That is limited account usage, not guaranteed permanent inference capacity; usage is metered and paid credits can be purchased. The provider says hosted inference may be served primarily in the US, with possible routing elsewhere, and that prompts/responses are not logged or used for training. Review current [pricing and terms](https://ollama.com/pricing). No `OLLAMA_API_KEY` is configured in the local project environment, so no hosted inference request was made or verified here. A zero-cost hosted AI deployment remains unverified until an account owner confirms included starter credit/model eligibility, supplies a server-side key, and approves sending synthetic text. Never let usage fall back to purchased credits under the strict ₹0 budget.

For a controlled synthetic smoke test, first verify free included credits and eligible model in the account, set `OLLAMA_RFQ_BASE_URL=https://ollama.com`, select a supported model in `OLLAMA_RFQ_MODEL`, add the key only to Render's API secret settings, then explicitly set `LOCAL_AI_ENABLED=true`. Use a synthetic fixture, a bounded request, and verify a pending `LOCAL_OLLAMA` suggestion with source evidence and estimator review. If included credits are unavailable, keep AI disabled; deterministic PDF/XLSX/EML extraction remains available. Live hosted inference, provider quota, and remote model compatibility have not been tested in this environment.

## Important limitations

- This is an assignment/demo architecture, not a production availability guarantee. Render Free can sleep/restart, allows only one instance, and can be suspended at usage limits. Neon Free has finite compute/storage and is not a substitute for independently tested backups.
- R2 free use is capped; above the published allowances, usage is billable. Monitor it and stop uploads before the cap.
- Render outbound traffic to database/object storage counts toward its included limits and can trigger suspension at unusually high volumes.
- The app currently allows a maximum 10 MB per uploaded document; the object storage adapter uses a single bounded request, suitable for that cap.
- Local Ollama in WSL cannot be reached by a cloud service. Hosted AI is optional and requires customer data approval plus included free quota; no hosted AI credential was available for this inspection.
- This branch has not been deployed. A public URL is valid only after an approved deployment and successful public health, login, role, upload/download, quotation/PDF, and AI-state checks.
